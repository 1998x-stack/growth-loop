# Decision Rules — Growth Loop

Operational heuristics, not validated psychometric scales. Keep competing hypotheses and update from evidence.

## 1. Choose a leverage capability

For every candidate, inspect **strength evidence (S)**, **external value (V)**, **sustained willingness (W)**, **transferability/compounding (C)** and **feasibility (F)**. Use a compact qualitative matrix (strong/mixed/weak/unknown) with an example of evidence for each cell. A 1–5 score is optional only when decision makers define anchors in advance; numbers are not scientific trait scores.

**Hard gates precede ranking:** unethical activity; unsafe burden; impossible access; a critical dependency that must be solved before practice is feasible. For unknowns, do an information-gathering experiment.

**Tie-break:** prefer an option with high external value, demonstrated improvement opportunity, low downside, and multiple future pathways. Do not automatically choose the current strongest skill; trajectory and changing demand matter.

**Stop list:** which existing activity has weak relevance, low learning yield, or high opportunity cost? Identify a concrete replacement.

## 2. Bottleneck differential

| If you observe | Test | Avoid concluding |
|---|---|---|
| Cannot explain or perform task steps | Demonstration with a checklist/mentor | "Not talented" |
| Can do parts but repeatedly misses outcomes | Change workflow, feedback channel or decomposition | "Just work harder" |
| Avoids one recurring low-risk next action | Make action small, safe, and time-bounded | Clinical or character diagnosis |
| Lacks authority/support/tooling/time | Check what additional capacity changes | "Needs more willpower" |
| Improves process but value does not grow | Test the problem/market relevance | "More process optimization" |

Use **one concrete incident**, ask what happened, what was expected, what else explains the gap, and what evidence would distinguish hypotheses.

## 3. Choose challenge intensity

Challenge is a **calibration**, not a stress prescription:
- Too easy: repetitive, no novel constraint or feedback.
- Productive: meaningful stretch with recoverability, feedback, and support.
- Too hard: no path to action, sustained overload, risk to health or obligations.

There is no published universal percentage of stretch to prescribe. Start smaller, test learning and recovery, then adjust.

## 4. Stop/adjust logic

- If quality improves and costs are sustainable, **continue**.
- If value is good but evidence shows the intervention did not work, **adjust** one variable and test again.
- If value is uncertain, **explore** alternative problems with low-risk probes.
- If value remains low or costs/risks are unacceptable, **stop** or renegotiate context.

Check **opportunity cost** explicitly: what could be learned or produced with the same time instead?

## 5. Example: engineer

Goal: Move from routine API maintenance to owning AI production systems.

Candidates: RAG evaluation, model tuning, public speaking. Do not score by popularity. Identify what actual organization/user problem exists; pick a deliverable with measurable user impact and tractable support.

Experiment: build a small evaluation dataset, ship one retrieval-quality improvement, compare answer relevance and latency against the baseline. Next week choose **continue/adjust/stop/explore**, with peer review.

## 6. Default report language

- **Observed:** what the user supplied or artifact shows.
- **Hypothesis:** current best explanation.
- **Unknown:** a variable that could change the decision.
- **Next test:** action that distinguishes interpretations.
- **Decision:** continue / adjust / stop / explore.
